✅ 一条直线，干净

✅ 没有额外的 Merge 节点

❌ 重写了 commit hash

❌ 已 push 的 commit rebase 会出事

场景 git merge git rebase

→ 大家 pull 后得到完全相同的 DAG

核心原理：Git 是"最终一致"的
短暂瞬间不同人的 git tree 不一样（取决于谁先 pull 了），
但合并完成后所有人 pull，看到的 DAG 完全相同。
因为 merge commit 只是新增一个节点，push 后大家都有。

⑧ 那 rebase 呢？为什么更危险

merge 不改变已有 commit

✅ 只新增节点，已有 commit hash 不变 → 全宇宙同一个 DAG

rebase 改写已有 commit hash

❌ chenbin pull → Git 发现 94347729 ≠ abc12345 → 冲突

⚠️ 这就是黄金法则的根源：
merge：加一个节点（merge commit），不动已有节点 → push 后大家 pull，DAG 一致。
rebase：改写已有节点 hash → 如果已 push，别人本地还有旧 hash，产生"分身"冲突。
